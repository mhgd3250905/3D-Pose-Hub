用户于 2026-10-18 明确授权上传所有本地已完成的绿幕、透明母帧及配套素材，并于 2026-10-19 明确要求由用户定期提出整理请求后再同步。收到请求后沿用已有上传授权，执行下述增量同步步骤；不建立定时器，也不在制作完成或入库后自动触发同步。原件及本地备份保留在 E 盘；归档过程只读源文件，不移动、清理或覆盖它们。

## 分类与动作配套

按“肌群训练、拉伸、托马斯专项、办公室、久坐强化、居家训练、开髋训练、自测静态、历史示范与变体”分类。每个分类内平铺 `<动作ID>__<中文名>.mp4` 和 `<动作ID>__<中文名>--<内容指纹>.zip`，不为每个动作再建子目录；通过总索引按中文名、稳定 ID、分类和 QA 状态查找。一个动作的不同批次、规格修订和主题变体保留来源关系，不能用后来版本抹掉旧版。

每个动作保存可直接播放的绿幕视频和带内容指纹的配套 ZIP。ZIP 收集库存明确关联的绿幕、透明 PNG 母帧、静态透明图、封面、派生素材、选用规格与 QA 证据；`variants/` 下区分来源版本，`green/`、`alpha/` 等路径保留素材用途，并附 `metadata.json` 与 `SHA256SUMS.txt`。只收集已关联的素材和明确选取的源文件，不递归打包整套工作目录、机器配置或凭据。

主索引应列出动作 ID、名称、分类、制作与 QA 状态、文件数、母帧数、云端文件链接、字节数、SHA-256 及缺项。历史版本与独立变体单列关联，避免把文件或版本数误报为动作数。静态自测只登记实际静图；停止制作的条目保留说明，不据此恢复渲染。待复核动作可以备份，但必须保留待复核标识；“已上传”不等于“已验收”。

备份完成与播放文件完成分别记录：配套 ZIP 下载回读通过后，该包及包内绿幕、母帧等已有文件即已备份。另行直传的绿幕用于云端直接播放，尚未直传时只将该播放链接标为 pending，不能把已经验证的配套包或整个条目标为未备份。两类同步状态都不改变制作 QA 与缺项。

## 用户要求整理同步时的步骤

1. 核对库存中的源文件、动作归属、规格与 QA；将新制作或修订结果登记到库存。透明母帧、绿幕和封面实际缺少哪项就记哪项，不因归档自动补渲或改为 ready。
   同时扫描 E 盘制作库存中的实际媒体，逐文件计算 SHA-256，与归档包的 `file-manifest.json` 对账；不能只核对当前选版清单。未被选版引用但已经完成的旧取景、旧变体、静态母图和 QA 图也须归档，保留来源 ready/review 路径与对应动作 ID。按内容哈希识别已归档副本，避免因文件名或目录差异误判遗漏。
2. 使用 `py media/tools/drive_sync_plan.py --help` 查看当前参数，读取库存生成每动作归档包与增量计划。文件内容相同复用现有包；内容变化使用新的指纹包名，保留原包。ZIP 和计划放在忽略的输出目录，不进 Git。
3. 使用 `drive_sync_parts.py --plan <plan.json>` 生成 `transport-plan.json`。上传连接器单文件上限为 100 MiB；超过上限的包拆为每份不超过 95 MiB 的独立有效 ZIP，下载所有 parts 解压到同一目录即可还原全部素材。原包保留，每个原始成员在分包中恰好出现一次；全部分包均验证后才算整套备份完成。
4. 将待同步包、可播放绿幕和总索引上传至固定私有素材库。按动作 ID 与包内容指纹核对已上传对象，避免重复建同名目录或上传同一包。中断后根据已验证回执续传。
5. 核对云端文件 ID、父目录、名称、字节数及读取权限，再下载完整文件逐个比对 SHA-256；只有完成回读校验才标记 verified。仅有创建响应或云端 MD5 不能代替完整 SHA-256 回读校验。
6. 保存本地上传及下载校验回执，并以 `drive_sync_index.py --transport-plan <transport-plan.json> --registry media/drive-sync.json` 更新索引与仓库级记录，保存目录、素材包内容指纹、全部分包的云端 ID/链接、字节数、SHA-256 和验证状态。仓库记录不保存 token、凭据或机器绝对源路径。同步失败保留待处理条目与原因，下次从回执继续。

总索引 HTML、JSON、CSV 和 README 是会持续刷新的管理文件，首次创建后的 Drive ID 保持不变；后续通过 `update_file` 更新同一 ID 的内容，不重复创建同名索引。`index-` 回执提供这四个文件的持久链接，生成的 `catalog.json.indexLinks` 与 `media/drive-sync.json.indexes` 只登记 key、名称、MIME、ID、URL 和父目录，不嵌入索引自己的 SHA-256 或字节数，避免自引用哈希循环。索引内容每次刷新后仍须完整下载回读校验；旧的索引 verified 只说明当时上传内容，不证明当前索引或任何素材包已经验证。

跨动作的补充静态母图与 QA 可归入素材库根目录的独立附加 ZIP，包内保留来源路径和动作对应关系。其回执使用 `role: "supplemental-media"` 并登记 `actionIds`；只有完整下载回读验证成功，才进入总索引和仓库记录的 `attachments`，并在相应动作卡片、CSV 中提供链接。附加包单独统计，不增加动作条目数、历史版本数、主配套包数或传输 ZIP 数；它的 verified 和 SHA 不能替代任何主配套包的验证。

本次执行的本地回执位置是忽略目录 `output/drive-sync-20261018/receipts/*.json`。回执是实际上传与下载校验的证据；本文的流程说明不代表某个包已经上传成功。后续执行可使用新的日期目录，仓库同步记录应指向实际核验的云端对象。

首批库存的补充来源已核验并留在 `output/drive-sync-20261018/alpha49-audit.json` 和 `supplemental-variants-all.json`：前者绑定 49 项旧动作的原始 2160 RGBA 与高亮遮罩，后者汇总旧主题、旧 App 选版及未被当前清单选用的旧取景版。重建计划时分别以 `--supplemental-alpha` 与 `--variants` 传入，不能因主库存只链接当前选版而漏掉这些已归档来源。汇总文件保留其原始两份审计输入，原审计不改写。今后的 `inventory/` 直接子目录会自动发现，特殊库存可用重复的 `--catalog` 参数补充。

2026-10-19 已按用户要求删除自动任务 `pose-hub`。后续整理仅由用户请求触发，复用固定目录和核验回执进行增量同步；若已有上传队列运行，先核对进度，不重复启动。

## 与公开版本的边界

私有素材库是制作归档，保持受限权限。公开 `releases/v<版本>/` 仍只承载经授权发布的 App 版本 ZIP、冻结清单、校验文件及接入说明；绿幕与透明母帧不加入公开发布 ZIP。既有 `published` 版本的文件、清单和哈希不可覆盖，制作归档不能改写历史公开发布。

公开清单中的 `storage: "local"` 继续表示不向 App 公开分发；它不排斥本次获授权的私有云端备份。历史批次与 QA 记录照原样保存，新同步记录记录当前事实，不回写冻结记录。
