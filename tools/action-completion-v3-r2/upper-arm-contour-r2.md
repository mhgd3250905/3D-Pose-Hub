# Upper-arm contour r2: proximal fullness candidate

This is a complete replacement for r1, not an additional layer. Installation rejects an existing r1/r2 component. It retains the exact r1 restraint at the shared torso/limb ring and adds a small proximal fullness field for the user's second arrow.

The marked surface is the upper arm's proximal/inner transition which faces backward in the bear-plank image. It has not been validated as a physiological triceps segmentation. Pixel samples in the r1 full-mesh capture identify shared-mesh vertices 17023/24437/32510 near 110 mm below the shoulder and 18993/24424/32483 farther down. Transporting image-backward direction through the actual upper-arm matrices shows that a fixed neutral-world -Z direction would target the wrong surface. Instead, each neutral upper arm uses the direction toward the opposite shoulder, projected perpendicular to its own shoulder–elbow axis. This neutral deformation follows the existing skeletal skinning in every pose; no current-world displacement is applied during animation.

The added field is restricted to shoulder distances about 88.87–148.87 mm, peaks at 118.87 mm, and only affects the inward 120-degree sector. A C1 axial window, smooth angular window and high-upper-arm-weight mask prevent abrupt boundaries. Maximum added displacement defaults to 4 mm; `install(page, {maxFillMm})` allows 0–5 mm. Zero exactly reproduces r1. The unchanged shared ring is about 163.87 mm from the shoulder, beyond the fill window. The original problem vertices 18329/35538/35539 receive zero added displacement, so r1's improvement there remains intact. No bones, poses, contacts, weights, indices, materials or frozen assets change.

CPU evidence: `F:/PoseHub-v2-production/elbow-review-20261029/upper-arm-contour-cpu-r2.json`, using the actual original neutral dump and actual r1 GPU neutral dump. Recomputed r1 agrees with GPU positions within 0.0000635 mm. Added fullness affects 249 left / 250 right vertices, with maximum 3.9041 / 3.8974 mm. The 56 ring copies remain identical to r1; original/candidate minimum face-normal dot remains 0.8741 and no triangles collapse or reverse. These are geometry checks, not visual approval.

Five CPU tests cover bilateral geometry, protected regions/weights, seam rejection, rigid-transform equivariance, zero-fill equivalence, bounded directional fill, and unchanged ring restraint. The runtime API is `window.__upperArmContourR2.measure()`, retaining the 56-pair actual-world measurement and 0.01 mm rejection threshold. `detach()` restores the original buffers.
