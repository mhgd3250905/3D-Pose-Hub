# Clip01 二维关键点

逐帧 JSON 文件以原片零基帧号命名，范围 `10118.json`–`10273.json`。每个文件的 `frame` 同文件名。坐标为同名 RGB 帧的 1920 × 1080 像素坐标，左上角为原点，X 向右，Y 向下。

## 点位和置信度

`keypoints` 每帧 135 项。ID 0–132 是 COCO-WholeBody 的 133 点。左/右身体手腕分别是 9/10，手部独立腕根是 91/112，中指根是 100/121。左脚的大脚趾、小脚趾、脚跟是 17/18/19，右脚相应为 20/21/22。ID 133/134 为左右掌心，根据同手腕根和四个掌指关节的像素均值推导。

RTMW-x 使用 384 × 288 输入，按原片中演示者的跟踪框分别以 0°、90°、180°、270° 入模。输出坐标还原至原片像素，根据相邻帧连续性和人工核对的手脚落点选取每帧解。JSON 的 `pose_rotation_deg` 记录所用输入旋转，`side_assignment` 为 `swapped` 的原片编号为 10196 和 10251。模型和接口来自 [OpenMMLab RTMW](https://github.com/open-mmlab/mmpose/tree/main/projects/rtmpose) 与 [RTMLib WholeBody](https://github.com/Tau-J/rtmlib/blob/main/rtmlib/tools/solution/wholebody.py)，使用 [RTMW-x ONNX](https://download.openmmlab.com/mmpose/v1/projects/rtmw/onnx_sdk/rtmw-dw-x-l_simcc-cocktail14_270e-384x288_20231122.zip)。ONNX SHA-256 为 `bd033156e5104c4f5d2edfe0453e02661e30a2f3da453ec93c8764d561b83054`。

`confidence` 保留 RTMW 原始 SimCC 峰值。分数越高表示网络响应越强，值可以超过 1，无法解释为概率。推导掌心的分数为有效组成点的最低分。组成点有任一警告时，掌心的 `x`、`y` 和 `confidence` 为 `null`。

## 人工核对

查看了 156 帧的左右侧彩色叠加，重点沿连续画面核对手部支撑、交叠和翻转。58 帧有人工可见性或错配标记，另有 3 帧主干关节缺少跨旋转一致性。共 61 帧标为 `side_review: "uncertain"`，范围如下。

`10137–10140、10144–10146、10157–10159、10165–10169、10179–10182、10187–10191、10196–10198、10202–10203、10209–10211、10217–10219、10224–10227、10235–10237、10239–10242、10246–10251、10256–10257、10262–10268`

`keypoints[].flags` 保留低分（原始分数小于 1.8）、超出人物轮廓 9 像素余量、跨旋转分歧和人工识别的遮挡或错配。跨旋转分歧表示还原坐标后，4 个模型输出中只有选中结果本身在 32 像素内。存在标记的原生点保持模型坐标和原始分数，`quality` 为 `flagged_estimate`。原生共 20,748 项，其中 2,549 项带标记。312 个掌心候选中 256 个可推导，左 19、右 37 个保留空值。支撑与接触以同目录上一级的人工标注和原片复核。
