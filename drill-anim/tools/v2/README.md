# Action package v2 layer renderer

`render_layers.mjs` is an independent runtime adapter. It uses the current production
model, frozen `lib/boot.mjs`, the original motion timeline, and the v2plus loader.
It does not edit frozen model/render sources or stretch animation timing.

Start the root Vite server using the port in ignored `drill-anim/config.json`.
Then run a preview before a complete render:

```powershell
node drill-anim/tools/v2/render_layers.mjs --spec drill-anim/specs/w-dead-bug-r2.js --action w-dead-bug --skin realistic --root F:/PoseHub-v2-pilot --frames 0,60,120,180,240
```

Omit `--frames` only after preview review: the complete sequence is frames 0–239
at 30 fps, 1080 square, eight seconds. Frame 240 is the eight-second QA endpoint
and is never included in the production index. Full production captures it in
`qa/endpoints/<skin>/<action>/` and records `qaEndpoint` references. Full runs
require `--reviewed`: matching source fingerprints, start/peak/end/endpoint
previews and every preview index/PNG SHA are checked before Chromium launches.
`--layers body,highlight,shadow` selects
passes (all three by default). Run one worker; Chromium TEMP/profile lives under
`<root>/work/browser-temp`.

`--skins all` runs the five production skins in one browser. Each timeline frame
is posed and measured once with the canonical model, then the other four body
images change only material uniforms. Equal measured geometry is required.
Canonical highlight/shadow sequences are shared by manifest reference; no
duplicate layer PNGs are written. `--no-share-layers` enables diagnostic
cross-skin byte comparisons. The
final pilot queue is `node drill-anim/tools/v2/run_pilot.mjs --root F:/PoseHub-v2-pilot --preview`.
It captures each action's declared peak plus frames 0, 239 and QA endpoint 240.
After viewing those samples, use the same command with `--reviewed` in place of
`--preview`. One browser runs at a time; each action has a persistent log and an
immutable source fingerprint. No source changes are allowed during a batch.

The five production skins are `realistic`, `tech-white`, `neon-night`,
`neon-night-b`, and `hologram`. `tech-white-b` is a code alias. `plaster` and
`hologram-b` remain experimental historical presets and are outside this pilot.

Complete outputs use `masters/<skin>/<action>/body/m-####.png`,
`highlight/k-####.png`, and `shadow/s-####.png`. Partial previews use
`qa/preview/<skin>/<action>/` to prevent passing previews off as masters.
Each layer has an `index.json` with ordered per-frame media-root-relative paths,
SHA-256 and bytes; the adjacent `layer-manifest.json` records dimensions, timing,
model manifest SHA, normalized source SHA, and sequence references.
`source-manifest.json` pins transitive spec imports, render adapter, frozen render
helpers, model inputs and runtime sources. Inputs are checked again at completion.
An existing complete-master directory with another recipe is refused. Development
previews may be regenerated and explicitly record the source fingerprint.
`occlusion-audit.json` includes body and prop meshes, transforms, canonical depth
rules and camera at reference time zero. `seam-qa.json` compares endpoint and wrap
pose, camera, exact PNG hash and pixel differences; the seam still needs viewing.

`python drill-anim/tools/v2/qa_layers.py --root F:/PoseHub-v2-pilot` checks actual
PNG dimensions, nonempty body/shadow, grayscale masks and absence of mask pixels
outside body coverage, producing `qa/preview-layer-pixels.json`. Add `--masters`
to measure all production frames and write `qa/masters-layer-pixels.json`.
After all six actions finish, run `tools/action-package-v2/audit_metrics.py` and
`tools/action-package-v2/qa_sequences.py` with the same `--root` to summarize
complete hand/finger geometry, support locks, elbows, seams, empty frames, canvas
clipping and area outliers. These reports are measurements, not visual approval
or exhaustive mesh collision detection. A non-supporting hand is allowed to use
its original free mode; zero QA samples must never be treated as a pass.

Body RGBA contains the selected material and props with muscle coloring disabled.
The mask RGB stores canonical designed v2plus muscle selection coverage, without
theme color, lighting or pulse. Its alpha contains the foreground silhouette;
compositors must use its RGB as coverage, constrained by body alpha. Props and
unselected surfaces remain black, depth-tested occluders. Canonical selection uses
the same analytic designed muscle field as the realistic production model; visual
region-outline styles do not alter this independent layer.

The floor shadow is a real directional-light shadow-map pass on a transparent
ShadowMaterial receiver, with body/props writing depth but no color. Each caster
uses a custom MeshDepthMaterial whose vertex shader is generated by the actual
active material hook, including breathing and cloth-sink deformation. Only the
fragment shader uses standard Three.js packed depth. `--shadow-probe` saves a
zero/displaced caster comparison without foreground depth occlusion; this checks
that shader deformation changes the shadow itself. Per-mesh source vertex hashes
and the probe pixel difference are recorded for review.

`geometry-audit.json` fingerprints actual visible mesh vertex attributes, indices,
draw ranges, groups, bind matrices and skeleton names/inverse matrices for each
production skin. Equal hashes establish geometry sharing for the current recipe;
they do not claim that a future extra-geometry skin can share masks. Camera, props,
action source and layer parameters must also match before reusing an action layer.
